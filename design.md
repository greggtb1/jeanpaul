# Design.md — Inspiration BloomHQ

## 1. Direction artistique générale

Le design doit s’inspirer d’une esthétique SaaS moderne, douce, accessible et très orientée conversion. L’univers visuel doit donner l’impression d’un produit intelligent, simple à utiliser, rassurant et presque ludique.

L’ambiance générale est :

* claire ;
* arrondie ;
* friendly ;
* dynamique ;
* légèrement Gen Z ;
* tech mais pas froide ;
* professionnelle mais pas corporate.

Le site ne doit pas ressembler à un outil B2B rigide. Il doit évoquer une application moderne que l’on comprend immédiatement, avec des parcours simples, des cartes visuelles, des étapes évidentes et une promesse très directe.

## 2. Principes visuels

Le design repose sur des blocs très lisibles, beaucoup d’espace blanc ou pastel, des coins arrondis, des cartes flottantes et des illustrations d’interface.

L’objectif est de transformer une action perçue comme complexe ou pénible en expérience simple et presque agréable.

Chaque section doit répondre à une question simple :

* Qu’est-ce que c’est ?
* Comment ça marche ?
* Pourquoi c’est plus simple ?
* Est-ce que ça marche vraiment ?
* Comment je commence ?

## 3. Palette de couleurs

Utiliser une palette douce, lumineuse et optimiste.

Couleurs principales recommandées :

* Fond principal : bleu très clair / mint très pâle.
* Fond secondaire : blanc cassé, crème très léger ou vert pastel.
* Texte principal : noir bleuté très foncé, presque marine.
* Accent principal : vert menthe / turquoise vif.
* Accent secondaire : violet ou bleu électrique en petite touche.
* Cartes : blanc, crème clair ou pastel très doux.
* Bordures : gris très clair ou vert très pâle.

La couleur ne doit jamais être agressive. Les accents servent surtout à guider l’œil vers les CTA, les statuts positifs, les coches, les éléments actifs et les illustrations importantes.

## 4. Typographie

Utiliser une typographie sans-serif arrondie, moderne et très lisible.

Style recherché :

* titres très bold ;
* formes légèrement rondes ;
* bonne lisibilité mobile ;
* ton chaleureux ;
* pas trop corporate.

Les titres doivent être gros, courts et très affirmés.
Les paragraphes doivent être simples, conversationnels et faciles à scanner.

Hiérarchie recommandée :

* H1 très large, centré ou aligné à gauche selon la section.
* H2 large, avec une formulation directe.
* Sous-titres courts, en gris foncé ou noir adouci.
* Corps de texte entre 16px et 18px.
* Boutons en semi-bold ou bold.

## 5. Layout général

Le layout doit être très aéré.

Structure recommandée :

1. Bandeau / header simple avec logo, navigation courte et CTA.
2. Hero très lisible avec grande promesse, sous-texte et bouton principal.
3. Illustration produit ou mockup d’interface à droite ou sous le hero.
4. Section “How it works” en 3 ou 4 étapes.
5. Section preuves sociales / témoignages.
6. Section CTA finale.
7. FAQ simple.
8. Footer complet mais léger.

Les sections doivent être bien séparées par des fonds légèrement différents ou des espacements généreux.

## 6. Hero section

Le hero doit expliquer la valeur en une phrase très claire.

Style du hero :

* grand titre impactant ;
* phrase courte orientée bénéfice ;
* CTA principal très visible ;
* mockup produit ou cartes flottantes ;
* fond pastel doux ;
* éventuels petits éléments décoratifs autour de l’interface.

Le hero ne doit pas surcharger. Il doit immédiatement faire comprendre :

* le problème ;
* la solution ;
* le bénéfice.

Exemple de logique :
“Fais moins d’efforts. Obtiens plus de résultats. Garde le contrôle.”

## 7. Composants UI

### Boutons

Les boutons doivent être arrondis, généreux et très visibles.

Bouton principal :

* fond vert menthe / turquoise ;
* texte foncé ou blanc selon contraste ;
* padding large ;
* coins très arrondis ;
* effet hover léger.

Bouton secondaire :

* fond blanc ou transparent ;
* bordure claire ;
* texte foncé ;
* hover avec fond pastel.

### Cartes

Les cartes sont un élément central du design.

Style :

* fond blanc ou crème ;
* coins très arrondis ;
* ombre douce ;
* bordure subtile ;
* padding généreux ;
* éventuels badges, tags, icônes, coches.

Les cartes peuvent représenter :

* une étape ;
* une fonctionnalité ;
* une offre ;
* un témoignage ;
* un élément d’interface produit.

### Badges

Utiliser des petits badges pour rendre les interfaces plus vivantes.

Exemples :

* “AI-powered”
* “Auto-apply”
* “New”
* “Smart matching”
* “Dashboard”
* “Fast setup”

Les badges doivent être arrondis, pastel, avec une typographie semi-bold.

## 8. Illustrations et mockups

Utiliser des illustrations d’interface plutôt que des photos réalistes.

Style :

* cartes empilées ;
* éléments d’application ;
* checkmarks ;
* petites icônes ;
* avatars simples ;
* dashboard simplifié ;
* barres de progression ;
* tags de catégorie ;
* états positifs.

Les mockups doivent être simplifiés, pas réalistes à 100 %. Ils doivent aider à comprendre la promesse du produit.

L’idéal est d’utiliser des interfaces “fausses mais crédibles” qui donnent immédiatement envie de comprendre le produit.

## 9. Ton éditorial

Le ton doit être direct, simple et conversationnel.

Éviter :

* le jargon technique ;
* les phrases trop longues ;
* les promesses floues ;
* les formulations corporate.

Préférer :

* des phrases courtes ;
* des verbes d’action ;
* des bénéfices immédiats ;
* des comparaisons simples ;
* une pointe de fun.

Le ton doit donner l’impression que le produit simplifie vraiment la vie de l’utilisateur.

Exemples d’intention :

* “Moins de stress. Plus d’action.”
* “Tout est centralisé.”
* “Tu gardes le contrôle.”
* “Un geste simple, le reste est automatisé.”
* “Arrête de perdre du temps dans des tâches répétitives.”

## 10. Sections recommandées

### Section 1 — Hero

Objectif : faire comprendre la proposition de valeur en moins de 5 secondes.

Contenu :

* grand titre ;
* sous-titre bénéfice ;
* CTA principal ;
* aperçu produit.

### Section 2 — Comment ça marche

Présenter le fonctionnement en 3 ou 4 étapes maximum.

Chaque étape doit avoir :

* une icône ou illustration ;
* un titre court ;
* une description très simple ;
* éventuellement une mini-carte UI.

### Section 3 — Fonctionnalités clés

Présenter les fonctionnalités comme des bénéfices, pas comme une liste technique.

Exemples :

* matching intelligent ;
* automatisation ;
* personnalisation ;
* suivi centralisé ;
* notifications ;
* dashboard.

### Section 4 — Preuves sociales

Ajouter des témoignages courts, visuels et rassurants.

Chaque témoignage peut inclure :

* avatar ;
* prénom ;
* résultat obtenu ;
* citation courte ;
* entreprise ou contexte si pertinent.

### Section 5 — CTA final

Reprendre la promesse principale avec un bouton clair.

Le CTA final doit être plus émotionnel que technique.

### Section 6 — FAQ

FAQ simple, directe, rassurante.

Les questions doivent lever les objections principales :

* Est-ce que je garde le contrôle ?
* Comment ça marche ?
* Est-ce sécurisé ?
* Est-ce automatique ?
* Combien de temps ça prend ?
* Que se passe-t-il après inscription ?

## 11. Spacing et arrondis

Utiliser des espacements généreux.

Recommandations :

* sections : 80px à 140px de padding vertical ;
* cartes : 24px à 40px de padding ;
* gap entre cartes : 20px à 32px ;
* border-radius cartes : 20px à 32px ;
* border-radius boutons : 999px ou 16px à 24px ;
* largeur max contenu : 1100px à 1240px.

Le design doit respirer. Ne pas compacter les éléments.

## 12. Animations

Animations légères uniquement.

Recommandé :

* apparition douce au scroll ;
* hover léger sur les cartes ;
* micro mouvement sur les mockups ;
* légère translation au hover ;
* changement d’ombre subtil.

Éviter :

* animations trop complexes ;
* effets 3D lourds ;
* transitions qui ralentissent la compréhension ;
* effets trop “template”.

## 13. Responsive

Le site doit être pensé mobile-first.

Sur mobile :

* hero en colonne ;
* CTA visible rapidement ;
* cartes empilées ;
* textes courts ;
* mockups simplifiés ;
* navigation réduite ;
* espacements conservés mais adaptés.

Le design doit rester très lisible sur écran mobile.

## 14. Ce qu’il faut absolument éviter

Éviter :

* design trop froid ;
* trop de noir ;
* trop de gradients ;
* UI trop complexe ;
* paragraphes longs ;
* jargon IA ;
* surpromesse technique ;
* style dashboard enterprise ;
* animations inutiles ;
* sections trop denses.

Le produit doit paraître simple, humain et efficace.

## 15. Résumé de la direction

Créer un site SaaS moderne, doux et très clair, inspiré de l’univers BloomHQ : pastel, arrondi, conversationnel, orienté bénéfice, avec des cartes visuelles, des étapes simples, des mockups produit et des CTA très visibles.

Le design doit donner l’impression que l’utilisateur peut comprendre, essayer et obtenir de la valeur très rapidement.
